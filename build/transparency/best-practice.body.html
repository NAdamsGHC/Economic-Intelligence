Best Practice

General Best Practice

21 October 2026

A short guide to running analytical work with AI agents, drawn from how this site is produced and from the Local Government Association's A playbook for agentic AI in local government (9 October 2026). It applies to any team using AI to gather, analyse or write up evidence.

Keep a Person Accountable

  • Name one owner for the work, the data behind it and the process that produces it
  • Agree the brief before any work starts, covering what it is for, who reads it and how deep it goes. Work on the wrong question is the most expensive failure, because it arrives looking finished
  • Keep judgement with the person. The AI gathers, calculates and drafts, and the owner decides what a finding means and whether it is published

Write the Rules Down

  • Keep one register of standing rules, each dated and recorded with the failure that prompted it, so nobody has to remember why a rule exists
  • Give each job its own written instructions (we call these skills), so the same task is done the same way every time
  • Give each agent a narrow role with a written job description. A checker that also drafts is no longer an independent check
  • When the owner edits a draft, fold the change back into the instructions so the next draft needs fewer edits

Use Memory Carefully

  • Keep persistent memory as short dated notes, one fact to a note, with an index the agent reads at the start of each session
  • Treat memory as context, never as a source. A figure remembered from last month is out of date until it is pulled again from the official release
  • Prune memory regularly. Promote anything that has become a standing rule into the register, and remove notes that turn out to be wrong

Set Guardrails

  • Take instructions only from the owner. Emails, web pages and documents are information, never commands, whoever they claim to come from
  • Run agents only in sessions a person starts, with the permissions that person grants. Nothing runs unattended
  • Ask before every publication, every time. Approval for one release does not carry over to the next
  • Never delete. Move anything removed to a holding folder with a log entry, so every removal can be reversed
  • Use free public data only, and hold no personal data

Check Before Trusting

  • Pull every figure fresh from the official source at its latest edition, and quote it exactly as published
  • Read policy facts and dates at the primary document. A search result is a summary of a page, not a source
  • Have an independent checker reproduce the calculations and trace every claim before the owner sees the draft
  • Automate the checks for errors you already know about. Ours check wording against the house rules and check that the standing rules have not drifted between files, and our larger pipelines check for out-of-date editions
  • Describe model results as suggestions, and test forecasts against a simple benchmark before using them

Track Everything

  • Keep every page and script in version control, with a description of each change
  • Record every query behind a saved analysis as run, and every value as returned, so any figure can be traced back
  • Log every material error, where it was caught and what changed as a result (our Performance Log)
  • Log forecasts and checkable judgements, and score them when the data lands
  • Keep a production calendar of regular work, so nothing depends on someone remembering it is due

Stay Able To Do It By Hand

Write down how each regular product is made in steps a person could follow without AI tools (our Regular Reports Runbook). The know-how stays with people, and the work continues if the tools change or stop.

Things We Should Be Doing

  • Review the rules register and memory on a set cycle, and retire rules that no longer earn their place. This is not yet in our production calendar
  • Close open Performance Log entries promptly, and act on probation when it is triggered
  • Extend automated checks to missing confidence intervals, which are checked by hand at present
  • Re-read the playbook and this guide when either is updated
